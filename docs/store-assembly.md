# 매장 3D 조립 — 아키스케치 도면 + 준공도면 → three.js

아키스케치 프로젝트 하나를 three.js 매장으로 다시 세우고, 준공도면을 겹쳐 검증하고,
렌더샷과 같은 시점에서 VMD 상품을 바꿔 끼우는 방법. 매장에 상관없이 같은 순서로 된다.
첫 적용: Discovery Expedition 명동 (`Z_qVQjfBCDE9007CAF64124`, 2026-10-27).

- 결과 화면: 프로젝트 상세 `/ko/projects/{projectId}` 의 탭 — (§10 매장연출 포함) `전체 렌더링`(기본, 천장·천장 부착물을 숨긴 매장 전체를 자유 회전/확대, WASD·방향키·R/F 와 화면 방향 버튼으로 이동, 오른쪽 드래그 회전·왼쪽 드래그 이동) · `렌더 샷`(아키스케치 렌더 이미지) · `3D 매장 보기`(렌더 시점 고정, 슬롯으로 상품 변경, 추가한 상품은 끌어서 옮기지 않음, 추가·변경은 탭을 옮겨도 유지되고 새로고침하면 초기화) · `도면`(준공도면).
  같은 뷰어가 `/ko/projects/{projectId}/store` 에도 있다.
- 스크립트: `scripts/build_store_scene.py`, `scripts/fetch_custom_items.py`, `tools/pdf2png/`
- 뷰어: `web/src/components/StoreViewer.tsx`, 데이터 타입 `web/src/lib/scene-types.ts`

## 0. 한 매장 조립 순서

```bash
# 1) 프로젝트 상세(도면 벡터·렌더·lightsettings) — Oxylabs 경유
python scripts/collect_projects.py --folder 국내          # 이미 받았으면 생략

# 2) 이 프로젝트 전용 가구 사본(customPath) 받기 — Oxylabs 경유
python scripts/fetch_custom_items.py <projectId>

# 3) 준공도면 PDF → PNG (평면도·입면도만 골라서)
cd tools/pdf2png && npm install
node titles.mjs "<준공도면.pdf>"                                    # 페이지별 도면 제목 목록
node render.mjs "<준공도면.pdf>" "../../assets/__프로젝트/<프로젝트폴더>/drawings" 2.0 44,45,50
node crop.mjs  <p044.png> <out.png> <x> <y> <w> <h> 4               # 외곽선 픽셀 읽기 (§4)

# 4) data/drawings/<projectId>.json 작성 (§4 형식)

# 5) 씬 빌드 → data/scenes/<projectId>.json
python scripts/build_store_scene.py <projectId>

# 6) 웹에서 확인: 렌더 시점 → '렌더 비교', 준공도면 정렬은 window.__store.debugTop(true) (§6)
```

`build_store_scene.py` 출력의 `누락` 이 0 이 아니면 가구 라이브러리에 없는 모델이다
(`data/scenes/<id>.json` → `floors[].missing[].productId`).

## 1. 입력 데이터

| 무엇 | 어디서 | 비고 |
|---|---|---|
| 방·벽·코너 | `data/projects/<id>.json` → `detail.data.floorplans[]` | `corners[].position` 이 mm 좌표 |
| 배치 가구 | 같은 곳 `floorplans[].items[]` | `position` / `rotation` / `scale` / `customPath` / `groupId` |
| 가구 3D | `data/catalog.json` → `assets/{localDir}/{stem}.glb` | `productId` 는 **제품 id 또는 컴포넌트 id** 둘 다 온다 |
| 전용 가구 | `items[].customPath` → `resources.archisketch.com/<customPath>` | 에디터에서 치수·재질을 바꾼 사본. 라이브러리보다 우선 |
| 렌더 시점 | `renders.renderings[]` + `lightSettings[<imageId>].camera` | |
| 준공도면 | 시공사 PDF (명동: enviniz 합본 144p) | 평면도가 정렬 기준 |

## 2. 좌표·단위

- 아키스케치 = **mm, Y-up, 바닥 = XZ 평면**. 뷰어는 매장 그룹을 mm 로 짓고 `scale 0.001` 해서 m 로 본다.
- 라이브러리 glb = 정점 mm + 루트 노드 `scale 0.001` → 로드하면 **m**.
- 전용 gltf(`customPath`) = 정점 mm, 노드 scale 없음 → 로드하면 **mm**. 버퍼는 `data:` URI 로 내장돼 있다.
- 층 높이: `floorplans[].floorHeight` 는 믿지 않는다(명동 2F 가 2300 으로 옴). 아래층 **방 높이(`rooms[].height`)** 를 누적한다.

## 3. 가구 배치 — 함정 4개

다 틀려 본 것들이다. 렌더샷 오버레이(§6)로만 잡힌다.

### 3-1. 기준점은 바운딩박스 **중심**
`position` 은 모델 원점이 아니라 **모델 바운딩박스 중심**이다.
라이브러리 glb 는 원점이 바닥, 전용 gltf 는 원점이 중심이라 원점 기준으로 놓으면 둘 중 하나가 어긋난다.
- 근거: 높이 3,222 mm 사이니지가 `y = 1611`, 높이 2,487 mm 전용 행거가 `y = 1243.5`.
- 처리: 모델을 `-center` 만큼 옮긴 뒤 행렬을 곱한다 (`items[].center`, 빌드 때 glb/gltf 헤더에서 계산).

### 3-2. 회전은 **전치(역회전)**
아키스케치 `rotation` 을 three.js Euler 로 그대로 쓰면 **회전이 반대로** 돈다.
대칭인 집기는 티가 안 나고, 매장 전체 바닥·벽 모델(`1F바닥`, `1층전체벽`)이 180° 돌아가서 입구에 계단이 생긴다.
- 근거: 같은 Euler 의 전치로 바꾸자 렌더 1번과 벽·프레임 행거·천장·포스터가 겹침.
- 처리: `M = T(position) · Rᵀ · S` (`item_matrix()`).

### 3-3. `localTransform` 쓰지 말 것
`localTransform` 은 **그룹(`groupsV2`) 기준 상대값**이다. 그룹 안 아이템(명동 1F 128/213)은
원점 근처에 몰린다(옷 80벌이 ±0.3 m 에 뭉쳤었다). `position`·`rotation`·`scale` 은 이미 **월드 값**이다
(그룹 180° + 로컬 −90° = 아이템 90°, 위치는 그룹 132개 전부 일치). 월드 값만 쓴다.

### 3-4. 버릴 것
- 면적 > 1,000 m² 방 = 부지/외부 (명동 1F 에 92 × 74 m 방). 그 방에만 걸친 벽도 버린다.
- 높이 < 10 mm 벽 = 가상 경계선 (명동 높이 2 mm).
- 이름에 `(렌더링x)` = 에디터 보조물. 렌더에 안 나오므로 뷰어에서 기본 숨김(`renderHidden`).
- 방 코너 목록의 연속 중복점.

## 4. 준공도면 정렬

1. **축척 표기를 믿지 않는다.** 같은 `1:100` 인데 PDF 를 A3 에 맞춰 줄여서 페이지마다 다르다
   (명동 2.0 배 렌더 기준 1F 19.85 mm/px, 2F 18.6 mm/px). 치수선으로 확인만 한다.
2. **외곽선 픽셀로 맞춘다.** `crop.mjs` 로 외벽 바깥선 좌·상·우·하 픽셀을 읽고,
   같은 층 아키스케치 방 범위 **± 벽두께/2** 에 대응시킨다. 이렇게 하면 가로·세로 축척이 1% 안에서 맞는다
   (벽두께를 빼먹으면 2.5% 어긋난다).
3. **방향을 먼저 정한다.** 평면도의 비대칭(입구, 계단실, 사선 벽)이 아키스케치 방 다각형 어느 쪽인지 본다.
   명동은 **이미지 위 = −z, 오른쪽 = +x** (뒤집힘 없음). 다른 매장은 다를 수 있다 — 다르면 `outlinePx` 에서 좌우/상하를 바꿔 넣지 말고 코드에 flip 옵션을 추가할 것.
4. 원근 때문에 벽 윗면이 부풀어 보인다. 확인은 **'위에서'(화각 12°, 거의 정사영)** 로 한다.

`data/drawings/<projectId>.json`:

```jsonc
{ "projectId": "...", "renderScale": 2.0,
  "pages": [
    { "page": 44, "file": "drawings/p044.png", "title": "1F 평면도", "floor": "Floor 1",
      "outlinePx": { "left": 454, "top": 661, "right": 1763.5, "bottom": 1016 } },
    { "page": 50, "file": "drawings/p050.png", "title": "1F 입면도 A" }      // floor 없으면 갤러리만
  ] }
```
`floor` 는 아키스케치 층 제목(`Floor 1`)과 같아야 겹치기에 쓰인다. `file` 은 프로젝트 assets 폴더 기준.

## 5. 렌더 시점 재현

`lightSettings[<imageId>].camera` 가 정답이다 (렌더 레코드의 `rotation` 은 Euler 라 순서가 애매하다).

| 항목 | 값 |
|---|---|
| 위치 | `camera.position` (mm, **층 바닥 기준**) + 그 층 level |
| 방향 | `camera.quaternion` 그대로 |
| 화각 | `camera.fov` = **세로** 화각 |
| 카메라 클립 | `camera.near` (mm). **바깥에서 벽 너머로 찍은 컷**이 많아서(명동 1번: 파사드 밖 x=−13,360) 이 값을 three 카메라 `near` 에 넣어야 앞 벽이 잘린다. 픽킹 레이도 같은 near 를 써야 안 보이는 벽에 상품이 붙지 않는다. |
| 층 | 렌더의 `floorplanId` 는 floorplan 의 **`archiId`** 다 (`id` 아님) |
| 화면 비율 | 렌더 해상도(`camera.resolution`) — 3840×2160 / 3000×3000 / 2160×3840 등 제각각. 뷰어 프레임을 그 비율로 바꿔야 오버레이가 1:1 로 맞는다 |

## 6. 검증 (매장마다 이것만 보면 된다)

1. **렌더 비교** — 렌더 시점 3~4개(가로/정사각/세로, 1F/2F 섞어서)에서 오버레이 50 %. 벽·천장 라인·행거가 겹쳐야 한다.
   - 큰 덩어리가 엉뚱한 곳에 있다 → §3-2 회전
   - 옷·소품이 원점에 뭉쳤다 → §3-3 localTransform
   - 높이만 어긋난다 → §3-1 기준점
2. **위에서 + 준공도면 겹치기** — 화면에는 버튼이 없다(시점 고정). 콘솔/헤드리스에서
   `window.__store.debugTop(true)` 로 현재 층을 위에서 보고 도면을 겹친다. 외벽·계단실·코어가 도면 선과 겹쳐야 한다.
   렌더 시점을 다시 누르면 원래 상태로 돌아온다.
3. `build_store_scene.py` 출력의 `누락` 수.

헤드리스 확인용으로 뷰어가 `window.__store = { THREE, camera, world, store, floorGroups, renderer, ceilings, debugTop }` 를 노출한다.

## 7. VMD 상품 배치

- 팔레트: `data/vmd-products.json` 의 `root` 폴더를 읽는다 (glb = m 단위, `mount` = `hang` | `place`)
  - `hang`: 모델 **상단 중앙(고리)** 이 레이 히트 지점에 온다 → 행거 봉을 가리키고 끌면 걸린다
  - `place`: 모델 **바닥 중앙** 이 히트 지점에 온다 → 바닥·선반·테이블
  - 벽처럼 수직면에 맞으면 상품 깊이 절반만큼 앞으로 뺀다
- 조작: 끌기 = 이동, `Q/E` 15° 회전, `Z/X` 높이 ±2 cm, `Del` 삭제.
- **카메라는 렌더 시점에 고정**이다(궤도·휠·WASD 없음). 시점 이동은 렌더 시점 목록 클릭뿐 — 렌더와 같은 화면에서 상품만 바꿔 보기 위한 결정(2026-10-27).
- 저장: 브라우저 `localStorage["vmd-layout:<projectId>"]` 자동 저장, `JSON 내보내기` 로 파일.
  형식 `{ uid, productId, position: [x,y,z] (m, 월드), rotationY }` (`Placement`).
- 상품 추가 = **파일만 넣으면 된다.** `data/vmd-products.json` 의 `root` 아래
  `<카테고리>/<스타일 폴더>/<스타일코드_컬러>.glb` + 같은 이름 `.png`(썸네일). 폴더가 그대로 웹 상품 탭 트리가 된다.
  명동: `assets/F&F/국내-명동/[디스커버리 명동]/상품/패딩/X26FDXDJ6M066 웰니스 다운 숏패딩/X26FDXDJ6M066_{SAD,BKS,DWS}.glb`.
  걸기/놓기는 카테고리(첫 폴더)별 `mount` (`{"패딩": "hang", "default": "place"}`).
  glb 는 미터 단위로 (Blender 기본 내보내기면 맞다). 무거우면(명동 패딩 97만 tri / 57 MB) 첫 로드가 느리다.

## 8. 한계 (명동 기준)

- 벽·바닥은 **마감재 색만** 쓴다. 마감재 텍스처(`finishes[].productId` → 마감재 라이브러리)는 아직 안 붙였다. 가구 glb 는 텍스처 포함.
- 조명은 환경광 + 태양 하나. 아키스케치 `lightSources` 는 안 쓴다 → 렌더만큼 사실적이지 않다.
  대신 색감을 렌더에 맞춰 둠: AgX 톤매핑 · 노출 0.85 · 환경광 0.55 · 따뜻한 반구광/태양(≈5,700 K) ·
  천장은 무조명 밝은 회색 · 캔버스 CSS `saturate(1.5) contrast(1.12) brightness(0.97)` (`CANVAS_GRADE`).
  기본 PBR 그대로면 렌더보다 노출이 과하고 바닥 테라조가 분홍으로 날아간다(렌더 1·8·12번 기준 비교).
- 개구부(`walls[].openings`)는 명동에 없어서 구현 안 했다.
- 명동 2F 모델 1개 누락 (`X3BgdYi9B4D03EADAE641D3`, 라이브러리에 없음).

## 9. 렌더 시점별 교체 슬롯 (L01, L02 …)

렌더에 이미 진열된 집기 위 상품(옷걸이&맨투맨 등)을 **번호로 지정해서 VMD 상품으로 바꾼다.** 첫 적용: 명동 렌더 #1 왼쪽 벽 행거 8벌.

1. 규칙 파일 `data/vmd-slots/<projectId>.json`:
   ```jsonc
   { "rules": [ { "shot": 1, "prefix": "L", "label": "왼쪽 벽 행거",
                  "names": ["옷걸이&맨투맨"], "u": [0, 0.3], "v": [0.5, 0.7] } ] }
   ```
   `shot` = 렌더 시점 번호(1부터), `names` = 아이템 이름, `u`/`v` = 화면 영역(0~1, 왼쪽 위 기준, 아이템 중심 기준).
2. `python scripts/build_store_scene.py <id>` → 아이템 중심을 그 렌더 카메라로 투영해서 영역 안의 것을
   **화면 왼쪽→오른쪽** 순서로 `L01…` 번호를 매겨 `shots[].slots = [{id, itemId, label}]` 에 넣는다.
   어떤 아이템이 어디 찍히는지 먼저 보려면 `project_to_shot()` 으로 시점의 아이템 목록을 뽑아 본다.
3. 뷰어: 그 시점에서 툴바 `상품 표시` 를 켜면 번호 배지가 뜬다(기본 꺼짐, 꺼져 있으면 옷 클릭도 안 먹음)(정면 진열이라 겹치는 옷은 배지를 한 줄로 펼치고 지시선으로 연결).
   배지나 옷을 클릭 → `상품 변경` → 상품 선택. 원래 아이템은 숨기고 상품을 **아이템 상단 중앙(고리)** 에
   **아이템과 같은 방향**으로 건다(`place` 상품은 아이템 바닥에 세움). `원래 상품으로` 로 되돌린다.
4. 저장: `localStorage["vmd-swaps:<projectId>"] = { [itemId]: productId }`.

## 10. 매장연출 (실제 매장 사진 → 명동 에셋 조립 장면)

프로젝트 상세의 `매장연출` 탭. 실제 매장 사진(`assets/.../[디스커버리 명동]/매장연출/0N_*.png`) 한 장을 **명동 라이브러리 부품으로 사진 그대로 다시 조립**한 장면이다. 아키스케치 렌더의 벽은 실제 매장과 구성이 달라서 쓰지 않는다. 상품 바꾸기는 `3D 매장 보기` 와 같다 (`상품 표시 → 번호 → 상품 변경`). 비교 버튼은 렌더 대신 참고 사진을 겹친다.

- 부품: `python -X utf8 scripts/build_vignette_parts.py` → `[디스커버리 명동]/부품/`. 큰 집기 안에만 있는 조각을 같은 메시·재질로 잘라 낸다.
